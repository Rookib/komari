# 离线升级与切换工具

这些工具配合 [1.6 升级说明](../../docs/upgrade-1.6-safe_zh.md) 使用。它们不代表发布或部署已完成。先在独立副本演练，再冻结生产写入并建立最终备份；不能把早先的演练副本直接替换生产数据。

## 工具范围

| 工具 | 用途与限制 |
| --- | --- |
| `../migrate-metrics` | 单独构建的离线迁移 CLI；只处理显式指定的数据目录及独立备份，不启动通知、网络服务或后台任务。容器使用 `--network none`。 |
| `audit_data.py` | 只读比对同一冻结源与其迁移结果；检查身份/账单摘要、通知表完整内容、非空流量计数及缺失集合。只输出计数、布尔值和摘要，不输出 UUID、IP 或凭据。 |
| `cutover.py` | 针对当前部署路径、旧容器配置和精确 Nginx 改动的操作脚本。默认只打印计划，`--self-test` 只使用临时目录及模拟命令。带 `--execute` 才操作实际部署。它不是适用于任意服务器的通用安装器。 |

`audit_data.py` 依赖相邻的 `../dmit-wan-calibrator/dmit_wan_calibrator.py`，分发时保留目录结构。审计的 `--legacy-timezone` 必须与迁移 CLI 和旧容器的时区一致；旧服务未设 `TZ` 时使用 UTC。缺失集合可以保留原来没有数据的节点，但源计数完全为空不能通过审计。

SQLite 临时存储配置使用磁盘文件。正式切换的迁移容器将该次运行目录下的私有 `migration-tmp` 绑定到 `/tmp`，不再使用 256 MiB 的 tmpfs 上限；切表、索引或空间回收可能需要额外临时磁盘空间。执行前仍须核对数据副本、回滚副本和迁移临时文件的总空间，不能把改用磁盘理解为没有容量限制。

审计只证明其覆盖的字段和最近累计值一致，不能代替指标存储的完整验证，也不能证明所有历史查询都正确。原数据库应已停止写入；SQLite 只读 WAL 访问仍可能触及临时 SHM 文件，因此切换工具使用停止后的原目录作审计源，独立回滚备份另行只读保留。

## 迁移日志的含义

迁移 CLI 按行输出 JSON。对于本次 SQLite 旧纳秒表转为规范化毫秒表的路径，阶段顺序如下；已是新结构或其他修复路径可能跳过其中部分阶段。

| `phase` | 含义 |
| --- | --- |
| `main_database` | 主库初始化、表结构与时间迁移。此阶段可能耗时，不提供逐表百分比。 |
| `copying` | 批量读取并复制旧原始点和汇总到临时重建表；`rows_done/rows_total` 是复制进度，不是全部工作进度。 |
| `preparing_statistics` | 仅 SQLite：对临时序列、标签、分辨率、汇总表执行 `ANALYZE`，帮助查询规划器先定位目标指标，再读取对应序列。 |
| `daily_rollups` | 按原有规则重建每日汇总。 |
| `compacting` | 按原有指标存储策略压缩和维护数据；并非跳过历史或修改保留设置。 |
| `validating` | 切换前检查临时表的规范化结构、汇总与摘要等约束。 |
| `switching` | 用已验证的表替换旧指标表。 |
| `completed` | 指标表重建步骤结束；外层迁移流程尚未结束。 |
| `reclaiming` | 外层指标存储工具回收空间，可能仍需较长磁盘操作。 |
| `copied` | 报告复制结果以及迁移前后大小，仍是 `status=running`。 |
| `verified` | 再次确认不再需要结构升级、完成主库 checkpoint 和关闭；成功记录为 `status=complete`。 |

只有最后的成功记录和退出码 0 同时满足，才算 CLI 完成。`completed`、`rows_done == rows_total` 或日志暂时没有变化都不是可以中止或启动生产服务的依据。后处理阶段不持续增加行数，也不提供可靠的剩余时间；停机预算应参考完整演练耗时，包含备份、迁移、回收和验收。

`ANALYZE` 只写入 SQLite 查询规划统计，目标是此次填充好的临时重建表。聚合公式、保留策略、字典值、首尾时间和摘要处理保持不变。回归测试既核对实际查询计划，也比较执行统计准备前后的完整汇总结果，并覆盖非 SQLite 驱动不执行该操作。不据此承诺固定倍数的加速。

## 切换日志与恢复

`cutover.py` 输出的是较粗的操作事件，如 `copying_independent_backup`、`migrating_offline`、`auditing_original_and_candidate`、`switching_data`、`starting_candidate`。它捕获子进程输出，不在自己的标准输出中实时转发迁移 CLI 的每个 JSON 阶段。需要检查迁移细节时，使用该次运行状态文件记录的迁移容器名称查看容器日志；不要推测名称或公开包含私有配置的 inspect/env 文件。

每次运行目录保存私有状态、原容器信息、独立备份摘要和审计结果。成功后保留旧容器、旧数据和备份；最终日志写出失败不会撤销已经完成的切换。出现错误则停止候选写入，按完整备份恢复旧数据、旧容器和相关服务状态。脚本被中断后的恢复使用该次运行目录的 `--rollback` 模式，不手工将新旧数据库文件混合覆盖。

生产执行必须固定候选镜像 ID，并传入预期构建 hash，核对版本和服务重启次数。HTTP 健康检查之后还应检查新前端资源、真实节点上报与流量显示。候选开始接收数据后如果回滚，这段新数据保留在失败候选目录中，不会自动合并到旧库；不能将此流程描述为所有失败场景都完全没有新增数据间隙。

## 本地验证

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools/deploy-safe-upgrade -p 'test_audit_data.py' -v
PYTHONDONTWRITEBYTECODE=1 python3 tools/deploy-safe-upgrade/cutover.py --self-test
```

上述测试不执行生产切换。正式交付还需按 [发布核验说明](../../docs/release-1.6-safe_zh.md) 检查最终提交、产物、校验值及镜像 digest。
